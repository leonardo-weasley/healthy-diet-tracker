# Healthy Diet Tracker · Android build handoff

> **Version**: `1.1.0` (versionCode `2`, package `com.hdt.diettracker`)
>
> **Source baseline**: `d99866d feat(android): harden WebView and ship rewritten glass UI` (use `git rev-parse HEAD` at packaging time)
>
> **Build method**: **no Gradle / no AndroidX**; `android/build.sh` calls JDK 17 + Android build-tools 34 directly
>
> **Target environment**: Linux, macOS, or Windows WSL2 (do not run from Windows cmd/PowerShell)

## 0. Read first: packaging only `android/` is not enough

`android/tools/build_www.py` renders Flask templates and static assets into the APK. It reads files at these relative paths:

```text
android/..                        ← repository root
├── app/templates/                ← 4 Jinja pages
├── app/static/                   ← style.css, page scripts
├── app/nutrition/food_database.json
└── app/ai/prompts.py
```

**If only the `android/` directory is copied to the build machine, step 1 (`build_www.py`) fails because `app/...` is missing.**

### Recommended: create a minimal build package with `git archive`

Run at the repository root (Git preserves LF and excludes ignored files such as `keystore/`, `build/`, `dist/`, `assets/www/`):

```bash
git archive --format=zip -o hdt-android-build.zip HEAD \
  android \
  app/templates \
  app/static \
  app/nutrition/food_database.json \
  app/ai/prompts.py
```

> This file lives at `android/BUILD_HANDOFF.md` and is included in the zip.
> If there are uncommitted changes, `git add` + `git commit` first; otherwise `git archive HEAD` will not include them.

### Manual package layout

```text
hdt-android-build/
├── android/
│   ├── BUILD_HANDOFF.md          ← this file
│   ├── build.sh
│   ├── README.md
│   ├── tools/                    ← build_www.py, make_icons.py
│   ├── web/                      ← splash, bottom navigation, local API, Keystore bridge, USDA
│   ├── vendor/chart.umd.min.js
│   ├── tests/                    ← optional Node unit tests
│   └── app/src/main/
│       ├── AndroidManifest.xml
│       ├── java/com/hdt/diettracker/
│       └── res/
└── app/
    ├── templates/
    ├── static/                   ← css/style.css, js/*.js
    ├── nutrition/food_database.json
    └── ai/prompts.py
```

**Do not package** (regenerated or machine secrets):

```text
android/build/
android/dist/
android/app/src/main/assets/www/     ← regenerated by build.sh
android/keystore/                    ← signing key, transfer separately and securely
**/__pycache__/
```

### Signing key options

`android/keystore/release.jks` is excluded by `.gitignore` and is **not** included in `git archive`. Three options:

1. **Recommended (development/test builds)**: do not ship an old keystore. Set `HDT_STORE_PASS` on the build machine and `build.sh` generates a new `android/keystore/release.jks`. Keep that keystore and password for future upgrades.
2. **Reuse an existing keystore**: transfer `release.jks` separately over a secure channel and provide the password through an environment variable. Never put the password in the zip, docs, or Git.
3. **Use your own production keystore**: set `HDT_KEYSTORE`, `HDT_KEY_ALIAS`, and `HDT_STORE_PASS`.

> After changing signing keys, an APK signed with the old key **cannot be installed as an update**; the old app must be uninstalled first. Confirm key ownership before a public release.

## 2. Build machine requirements

| Component | Version / notes |
|---|---|
| JDK | **17** (must be a JDK with `javac` and `keytool`; a JRE is not enough) |
| Android build-tools | **34.0.0**: `aapt2`, `d8`, `zipalign`, `apksigner` |
| Android platform | `android.jar` from **android-34** |
| Python | 3.9+, with `jinja2` |
| Shell tools | `bash`, `find`, `sed`, `rm`, `zip`/`unzip` |
| Node.js | 18+, only for the optional `android/tests/core.test.js` |
| Paths | Repository path **must not contain spaces or non-ASCII characters** (`javac @sources.txt` does not quote entries) |

Install the Python dependency:

```bash
python3 -m pip install --user jinja2
# or in a virtual environment:
# python3 -m venv .venv && . .venv/bin/activate && pip install jinja2
```

Common SDK locations:

```text
Linux:   ~/Android/Sdk
macOS:   ~/Library/Android/sdk
Windows: %LOCALAPPDATA%\Android\Sdk   (in WSL: /mnt/c/Users/<you>/AppData/Local/Android/Sdk)
```

If no SDK is installed, use `sdkmanager`:

```bash
sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"
```

> `platform-tools` is not required to build; it is only useful for `adb install`.

## 3. Environment variables (important)

`build.sh` defaults reflect the author's non-standard layout:

```text
SDK default        /root/android-sdk
build-tools default  $SDK/android-14
platform default     $SDK/android-34-ext12/android.jar
JDK default          /root/jdk17
```

**With a standard SDK layout, setting only `ANDROID_SDK` is often not enough**; set these two explicitly:

```bash
export JAVA_HOME=/opt/jdk-17

export ANDROID_SDK=/opt/android-sdk
export ANDROID_BUILD_TOOLS="$ANDROID_SDK/build-tools/34.0.0"
export ANDROID_PLATFORM="$ANDROID_SDK/platforms/android-34/android.jar"

# Signing password: never commit it or write it to docs/build logs
export HDT_STORE_PASS='replace-with-a-strong-password'

# Optional
export HDT_KEYSTORE=/secure/path/release.jks   # default android/keystore/release.jks
export HDT_KEY_ALIAS=hdt                       # default hdt
export HDT_BUILD_DIR=/tmp/hdt-apk-build        # default /tmp/hdt-apk-build
```

Notes:

- `ANDROID_PLATFORM` must point to the **`android.jar` file itself**, not a directory.
- `ANDROID_BUILD_TOOLS` must point to the directory containing `aapt2`, `d8`, `zipalign`, and `apksigner`.
- If `HDT_KEYSTORE` does not exist, the script generates a development keystore using `HDT_STORE_PASS`.
- If `HDT_STORE_PASS` is empty, the script exits immediately by design.

## 5. Build

At the repository root (the level containing `android/` and `app/`):

```bash
bash android/build.sh
```

The script runs:

```text
1/7  python3 android/tools/build_www.py      ← regenerate assets/www (23 files)
2/7  aapt2 compile / link                    ← resources + Manifest + assets
3/7  javac -source 11 -target 11             ← compile against android.jar
4/7  d8 --min-api 24                         ← generate classes.dex and add it to the APK
5/7  zipalign -f -p 4
6/7  apksigner sign                          ← uses HDT_STORE_PASS
7/7  apksigner verify + aapt2 dump badging   ← self-check
     package dist/HealthyDietTracker-1.1.0.apk.zip
```

The last lines of a successful build look like:

```text
APK  (inside zip): HealthyDietTracker-1.1.0.apk
Release bundle:    dist/HealthyDietTracker-1.1.0.apk.zip
```

> `javac` may warn that `source/target value 11 is obsolete` or about the bootstrap classpath; ignore those. Only `error:` lines matter.

`build.sh` regenerates `android/app/src/main/assets/www`; a normal build has **23 files**:

## 7. On-device acceptance checklist

A successful build does not prove the features work. Walk through at least this list:

- [ ] Cold start in airplane mode: splash appears, can be skipped, home page does not go blank.
- [ ] Top-right `⋮` → API settings: save a key; kill and reopen the app; the key is still there.
- [ ] After saving the key, kill and reopen; it still works. The key must not appear in page source or logs.
- [ ] Upload page: gallery picker and camera entry both open; cancelling does not crash.
- [ ] Upload photo → AI recognition → result page: food rows, weights, and standard-food dropdown work.
- [ ] On an unmatched row, tap "USDA match": search, select, auto-match; nutrition recalculates immediately after selection.
- [ ] Change "Standard food": calories/protein/carbs/fat update (the `change` event is not lost).
- [ ] Save a meal → visible in History → expand details; delete and pagination work.
- [ ] When focus enters an input and the keyboard opens, the bottom capsule navigation and save bar slide out of view; they return when the keyboard closes.
- [ ] Home charts, macros, and meal-type breakdown work; no remote Chart.js request.
- [ ] Back button and bottom navigation (Today / Log / History) work.
- [ ] Screenshots are blocked by `FLAG_SECURE` (expected behavior, not a bug).

## 8. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `missing build tool: .../aapt2` | Wrong `ANDROID_BUILD_TOOLS`; confirm it contains `aapt2`, `d8`, `zipalign`, `apksigner` |
| `missing android.jar` | `ANDROID_PLATFORM` must point to the file itself, not `platforms/android-34/` |
| `javac not found` | `JAVA_HOME` points to a JRE or wrong directory; check `$JAVA_HOME/bin/javac` |
| `invalid source release: 11` | JDK too old; use JDK 17 |
| `No module named jinja2` | `python3 -m pip install jinja2` |
| `python3: command not found` | Install Python 3 or point `python3` at `python` |
| `HDT_STORE_PASS is not set` | `export HDT_STORE_PASS='...'` |
| `keystore password was incorrect` | The existing `release.jks` password differs from `HDT_STORE_PASS`; use the correct password or remove the old keystore and regenerate |
| `Permission denied` running `build.sh` | `bash android/build.sh`, or `chmod +x android/build.sh` |
| `bad interpreter: /usr/bin/env bash^M` | Packaged with CRLF; repackage with `git archive`, or run `sed -i 's/\r$//' android/build.sh` on the build machine |
| `FileNotFoundError: app/templates/...` | Only `android/` was packaged; add the four `app/` paths from section 0 |
| `aapt2`/`d8` Java version error | build-tools too old or JDK too new/old; use build-tools 34.0.0 + JDK 17 |
| Install fails after `zipalign` | Make sure `HDT_BUILD_DIR` does not point to a read-only directory; rebuild completely |

## 9. Security and delivery notes

- **Never put `android/keystore/`, `HDT_STORE_PASS`, or any API key in a zip, Git, or chat.**
- The APK contains no built-in AI/USDA key. Users enter keys in settings; on Android they are encrypted with Android Keystore AES-256/GCM and written to `SharedPreferences` (`hdt_secure`).
- Native requests are HTTPS-only. The WebView CSP is `script-src 'self'` with no `unsafe-inline` and no remote scripts, fonts, or images.
- `FLAG_SECURE` blocks screenshots and screen recording by design.
- If reusing this build's `android/keystore/release.jks`, confirm its password; otherwise regenerate it per section 0 and store it safely.

## 10. Changes in this build

- English localization across the full chain: UI text, templates, frontend scripts, nutrition database display names, AI prompt, native bridge messages, tests, and documentation.
- AI requests and responses are English; the JSON schema is unchanged.
- Version bumped to `1.1.0` (versionCode `2`).
- Liquid Glass frontend: `style.css`, `app.css`, four page templates, splash structure.
- `android/web/js/keyboard.js`: hides the bottom navigation/save bar when the keyboard opens; external script to satisfy CSP.
- API keys moved to Android Keystore (AES-256/GCM); legacy plaintext `localStorage` values are migrated and removed automatically.
- USDA matching, auto-match, and custom food storage.
- Security hardening: HTTPS-only bridge, origin checks, 5 MB response limit, CSP, security headers, camera cache cleanup, `FLAG_SECURE`, provider path validation.

## 11. Optional: CI notes

For GitHub Actions or another CI:

1. Use `ubuntu-latest` + Temurin JDK 17.
2. Install/confirm `build-tools;34.0.0` and `platforms;android-34`.
3. Put `HDT_STORE_PASS` (and a base64-encoded keystore if you need stable signing) in CI secrets and decode it to a temporary directory during the build.
4. Set `ANDROID_BUILD_TOOLS`, `ANDROID_PLATFORM`, and `JAVA_HOME`, then run `bash android/build.sh`.
5. Upload `dist/HealthyDietTracker-1.1.0.apk.zip` as an artifact.
6. Never print secrets in logs; keep only certificate fingerprints from signing output.
