Features

Everything you need. Nothing you don't.

Built around one idea: logging a meal should take seconds, and the numbers behind it should be ones you can actually trust and trace.

Photo-first logging

Upload a JPEG, PNG or WebP up to 8 MB, with instant preview and meal-type selection — breakfast, lunch, dinner or snack.

AI food recognition

A multimodal model answers with structured JSON: food name, estimated weight and confidence. No API key? A bundled mock provider keeps the flow runnable offline.

Deterministic nutrition engine

Calories and macros come from our own pure functions over a 29-food USDA-backed library — reproducible to 0.01, unit-tested, and zero API cost.

Correct before you save

Edit any food name or weight and the backend recomputes on the spot. Unknown items are never silently filled with defaults — you are always asked.

Dashboard & charts

Chart.js renders daily calories against your goal, a macro donut and your most recent meals — all aggregated from local SQLite.

History you own

Query by date or range, open any entry, delete it. The whole diary is a single SQLite file — private, portable, and trivially backed up.

🧪 No API key needed. The bundled mock provider serves contract-compliant results on localhost.
📦 Android offline APK. The same pages, engine and storage packaged as a native WebView build.
✅ 184 tests green. Upload → recognize → correct → save → dashboard → history → delete.

How it works

AI names the food. Our code does the math.

One rule holds the whole project together: the model answers what this is and roughly how heavy it is — it never decides a single calorie. Every number on screen comes from a deterministic local function you can trace, test and explain.

01

Upload

Drop in a meal photo (≤ 8 MB). The browser previews it and lets you pick the meal type.

02

Recognize

The vision model returns a contract-A JSON list: food name, estimated grams, confidence.

03

Compute

Pure Python functions look up the local 29-food library and calculate calories and macros.

04

Log & chart

Confirm or correct, save to SQLite, and the dashboard and history update instantly.

AI never computes nutrition. No calorie or macro field may appear in the AI module.
Nutrition never goes online. The engine imports no HTTP client or AI SDK.
Frontend never touches data. The browser may only call /api/v1/*.
One AI client. Only app/ai/client.py imports the vendor SDK — providers are swappable.

Quick Start

Running locally in under a minute

Standard Python workflow — clone, virtualenv, install, initialize, run. The README has the exact commands for Windows, macOS and Linux.

  1. 1
    Clone & create a virtual environmentPython 3.11 or newer is required; grab the source with git or a ZIP download.
  2. 2
    Install dependenciesOne pip install -r requirements.txt — Flask, SQLAlchemy, Pydantic, Pillow, pytest.
  3. 3
    Initialize datainit_db.py creates the three tables; seed_foods.py imports 29 USDA-backed foods (safe to re-run).
  4. 4
    Runpython scripts/start_dev.py boots the app and the local mock AI together, then open 127.0.0.1:5000.
# 1. clone & create a virtual environment
git clone https://github.com/leonardo-weasley/healthy-diet-tracker.git
cd healthy-diet-tracker
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

# 2. install dependencies
pip install -r requirements.txt

# 3. initialize database & food library (29 USDA foods)
python scripts/init_db.py
python scripts/seed_foods.py

# 4. run — starts the app and the local mock AI
python scripts/start_dev.py
# → http://127.0.0.1:5000

No AI key? scripts/mock_ai_provider.py serves an OpenAI-compatible endpoint on localhost:5100 — start_dev.py wires it up automatically, and switching to a real key is three lines in .env.
